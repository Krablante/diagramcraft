# Разработка

[English](./CONTRIBUTING.md) · [Русский](./CONTRIBUTING.ru.md) · [Главная](./README.ru.md)

Спасибо, что заглянули. Проект намеренно небольшой: чистый ESM-пакет без шага сборки и с документированной спекой. Рендер использует ELK и resvg, плагин — Zod для аргументов инструментов. Быстрее всего начать так:

```sh
git clone https://github.com/Krablante/dorpie
cd dorpie
npm ci
npm run check
node bin/dorpie.js render examples/quickstart.json --format svg,png,ascii --out /tmp/dorpie-preview/
```

Нужен Node 20 или новее; CI гоняет проверки на Node 20, 22 и 24.

## Команды репозитория

| Команда | Что делает |
| --- | --- |
| `npm test` | Запускает набор `node:test` (валидация спеки, рендер, smoke-тесты CLI). |
| `npm run typecheck` | Запускает `tsc --noEmit` с `checkJs` по JSDoc-типам. |
| `npm run check` | Проверка типов, затем тесты; это обязательный гейт для изменения. |
| `npm run metrics` | Пересобирает `assets/fonts/metrics.json` после правок шрифтов. |
| `npm run gallery` | Рендерит картинки `docs/gallery` из `examples/`; запускать после визуальных правок. |

## Как всё устроено

Конвейер намеренно линейный:

```
spec JSON → валидация + тема → пиксельная раскладка (ELK) → SVG → PNG (resvg)
                           → символьная раскладка (ELK) → ASCII
CLI / плагин → библиотека → версии исходников + сохранённые экспорты → рендер
```

| Файл | Ответственность |
| --- | --- |
| `src/spec.js` | Разбор и валидация JSON-спеки; единственное место, задающее её форму. |
| `src/themes.js` | Загрузка встроенных тем и файлов тем, слияние переопределений. |
| `src/text.js` | Измерение и перенос текста по метрикам встроенных шрифтов. |
| `src/layout.js` | Спека + тема в геометрию через ELK; зоны и нормализация. |
| `src/shapes.js` | Общие контуры фигур и геометрия границ для отрисовки и привязки связей. |
| `src/svg.js` | Геометрия в SVG; единственное место, где токены превращаются в краску. |
| `src/ascii.js` | Спека в ASCII/Unicode-сетку через отдельную символьную раскладку. |
| `src/png.js` | SVG в PNG через resvg и встроенные шрифты. |
| `src/index.js` | Публичный API (`render`, `parseSpec`, помощники тем). |
| `src/cli.js` | Только разбор аргументов, файловый ввод-вывод и коды возврата. |
| `src/library.js`, `src/config.js` | Неизменяемые версии работ, история экспортов и общие настройки. |
| `src/opencode-plugin.js`, `src/plugin-install.js` | Инструменты агента и установщик, сохраняющий конфиг. |

Инварианты, которые нужно сохранять:

- **Спека — единственный редактируемый источник.** Сгенерированные SVG/PNG/ASCII — это вывод; ничего не должно требовать их правки.
- **Темы — это данные.** Встроенные темы лежат в `themes/*.json` и сливаются поверх `themes/_base.json`. Не добавляйте в рендерер ветки под конкретные темы; добавляйте токены или примитивы.
- **Без шага сборки и скрытого рантайма.** Чистый ESM с зависимостями рендера `elkjs`, `@resvg/resvg-js` и схемами аргументов плагина из `zod`. Не добавляйте бандлер или транспайлер.
- **Детерминированный вывод.** Одна и та же спека с одной темой должны давать байт-в-байт одинаковый SVG. Встроенные шрифты остаются в `assets/fonts/` вместе с OFL-лицензиями и пересобираются через `npm run metrics`.
- **PNG считается локально.** Без браузера, сети и системных шрифтов по умолчанию.
- **ASCII и SVG раскладываются отдельно** (символьные ячейки против пикселей); оба используют одну спеку и общий движок раскладки.

## Как вносить изменения

- **Спека или валидация:** обновите `src/spec.js`, `schema/diagram.schema.json`, `docs/spec.md` и `docs/spec.ru.md`, а также тесты в `test/spec.test.js`. Опубликованная схема и валидатор должны совпадать.
- **Рендерер, раскладка или тема:** отрендерите пример в затронутых темах и посмотрите PNG (композиция, подписи, пересечения, контраст). Выполните `npm run gallery` и закоммитьте обновлённые картинки. Изменения токенов отразите в `docs/themes.md` и `docs/themes.ru.md`.
- **CLI:** обновите `src/cli.js`, его текст `HELP`, `docs/cli.md` и `docs/cli.ru.md`, а покрытие команды оставьте в `test/cli.test.js`.
- **Библиотека/плагин:** общая логика находится в `src/library.js`; CLI и плагин — адаптеры. `test/library.test.js` проверяет сохранение, конфликты, экспорты, разрешения и установку. Обновляйте `docs/library*` и `docs/plugin*` вместе. Неизменяемые версии исходников и производные экспорты хранятся отдельно.
- **Примеры:** `examples/` работает и документацией, и тестовыми фикстурами; держите каждый файл валидным и показательным. `scripts/gallery.mjs` рендерит их в `docs/gallery`.
- **Документация:** обновляйте затронутые страницы на всех поддерживаемых языках; правило описано ниже.

## Документация

Английский использует базовое имя файла (`README.md`, `docs/cli.md`), переводы добавляют код языка перед `.md` (`README.ru.md`, `docs/cli.ru.md`). Сейчас доступны английский и русский. Украинский добавляется как `.uk.md`, немецкий — как `.de.md`, любой другой язык — тем же способом. Добавьте его в переключатель языков каждой страницы, а внутренние ссылки ведите на страницы этого перевода. Список файлов пакета автоматически включает новые языковые версии.

Сохраняйте одинаковые категории и порядок разделов во всех языках, но пишите естественно для каждого. При изменении поведения обновляйте смысл вместе. Примеры, схемы и галерея общие. Установка начинается в README; подробности CLI живут в `docs/cli`, хранение и настройки — в `docs/library`, подключение плагина — в `docs/plugin`, справочники спеки, тем и API — на своих страницах, работа агента — в `docs/agents`, разработка и релизы — здесь. Ссылайтесь на основную страницу темы вместо повторения всего справочника.

## Как добавить тему

1. `dorpie themes classic > themes/your-theme.json` (или скопируйте любую тему).
2. Задайте уникальные `id` и `title`; `description`, `tags` и `order` — необязательные метаданные.
3. Поменяйте типографику, формы, линии, фон и акцент — тема должна читаться как другая визуальная система, а не как перекраска.
4. Отрендерите диаграмму с развилкой, заметкой, группой и акцентным узлом; посмотрите PNG.
5. `npm run check && npm run gallery`; скрипт галереи сам включает все встроенные темы.
6. Добавьте превью новой темы в таблицу в README (оба языка) и в список тем в `docs/themes.md` + `docs/themes.ru.md`.

## Pull request

Держите изменение сфокусированным; опишите, что поменялось и как это проверено (команды и короткая визуальная заметка для правок рендерера или темы). Для пользовательских изменений обновляйте `CHANGELOG.md` и `CHANGELOG.ru.md`.

## Релизы

1. Выполните `npm version X.Y.Z --no-git-tag-version`, чтобы обновить `package.json` и lockfile. Обновите все переводы истории изменений.
2. Обновите версионные URL установки в README и руководствах по агенту, плагину и API на всех языках.
3. `npm run check`, `npm pack --dry-run`, затем установите собранный tarball в отдельный префикс и отрендерите пример.
4. `npm run gallery`, коммит, тег `vX.Y.Z`, пуш.
5. Создайте GitHub-релиз с описанием и приложите tarball из `npm pack` и `SHA256SUMS` (`sha256sum dorpie-X.Y.Z.tgz > SHA256SUMS`). Артефакты упаковки храните вне репозитория. Установите именно этот архив там, где есть рабочий рантайм, проверьте CLI и перезагрузите бэкенд, использующий плагин.
6. `npm publish --access public` — только с валидным npm-токеном; публикация сейчас не настроена, поэтому канал распространения — GitHub-релиз.
