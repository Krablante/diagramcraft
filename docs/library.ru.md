# Сохранённые диаграммы

[English](./library.md) · [Русский](./library.ru.md) · [Главная](../README.ru.md)

CLI и плагин OpenCode используют одну библиотеку работ. У сохранённой диаграммы есть постоянный ID, название, описание, теги и необязательная метка проекта. Сессия хранится как информация о происхождении: удаление чата не удаляет диаграммы.

## Сохранение, открытие, редактирование

```sh
dorpie save diagram.json --name "Deploy flow" --tags deploy,release
# Скопируйте полученный id. Все команды библиотеки выводят JSON.
dorpie list "Deploy flow"
dorpie get <id> --spec > edited.json
# Отредактируйте edited.json. Номер версии берите из get/history.
dorpie save edited.json --id <id> --expected-revision 1 --change "Add retry"
dorpie export <id> --theme glass
dorpie history <id>
```

`save` создаёт версию 1. Для изменения существующего ID нужен `--expected-revision`; устаревший или отсутствующий номер приводит к ошибке `CONFLICT`. Прочитайте диаграмму снова, согласуйте изменения и сохраните. Каждая версия содержит собственный проверенный JSON и метаданные. `--name`, `--description`, `--tags`, `--project` и `--change` задают метаданные; пропущенные значения сохраняются из прошлой версии, кроме комментария к изменению, который относится к новой версии. Метка проекта новой диаграммы в CLI — текущая папка, в плагине — корень worktree.

`get <id>` возвращает метаданные, редактируемый `spec` и архивный путь `specPath`. Этот путь используется только для чтения: редактируйте рабочую копию или полученный объект спеки и сохраняйте новую версию. `--spec` выводит только JSON для редактирования. `--revision N` открывает старую версию. Используйте ID, который вернул Dorpie; названия могут повторяться.

`list [query]` ищет по названиям, описаниям, тегам, ID и меткам проекта во всей библиотеке. `--project PATH` требует точного совпадения метки. `--limit` по умолчанию 50, максимум 200; `--offset` по умолчанию 0. Результат содержит `total` и `nextOffset`.

`history <id>` возвращает списки `revisions` и `exports`, начиная с новых, отдельные счётчики и `nextOffset`. Одинаковые `--limit` и `--offset` применяются независимо к обоим спискам. Поиск читает метаданные, а не исходники схем и изображения.

## Сохранение экспортов

```sh
dorpie export <id> --revision 1 --format svg,png --theme paper --scale 3
dorpie export <id> --export-dir ./deliverables
```

По умолчанию экспортируются SVG, PNG и ASCII, независимо от `output.formats` в спеке. Остальные параметры берутся из спеки и обычных настроек рендера. Каждый экспорт связан с одной версией исходника и получает отдельную папку `<exportDir>/<diagramID>/<exportID>/`. В ней лежат `diagram.svg`, `diagram.png` и/или `diagram.txt`, а также `spec.json`, полностью разрешённая тема `theme.json` и `export.json` с параметрами, версией Dorpie и SHA-256 файлов. Старые файлы не перезаписываются. Ошибки рендера не добавляют успешных экспортов в историю. Другая тема или масштаб экспорта не создают новую версию исходника.

История экспортов остаётся в библиотеке, даже если позже выбрать другую папку выгрузки. Перемещение или удаление файлов вне Dorpie делает записанные пути недоступными. Включайте библиотеку и папки экспортов в резервные копии.

Обычный `dorpie render spec.json` сохраняет прежнее поведение без библиотеки, включая перезапись результатов и `--out`. Он подходит для временных рендеров, потокового вывода и генерации документации. Для сохранённых работ используйте `export`; его папка задаётся через `--export-dir`.

## Настройки

Настройка не обязательна. На Linux библиотека по умолчанию находится в `$XDG_DATA_HOME/dorpie` или `~/.local/share/dorpie`, экспорты — в `<libraryDir>/exports`. На macOS папка данных — `~/Library/Application Support/dorpie`, на Windows — `%LOCALAPPDATA%/dorpie`.

Необязательный конфиг — `$XDG_CONFIG_HOME/dorpie/config.json`, обычно `~/.config/dorpie/config.json` (Windows: `%APPDATA%/dorpie/config.json`):

```json
{
  "libraryDir": "~/diagrams/library",
  "exportDir": "~/diagrams/exports"
}
```

`dorpie settings` показывает абсолютные пути, не создавая папок. Приоритет: явные параметры CLI/библиотеки/плагина, затем `DORPIE_LIBRARY_DIR` и `DORPIE_EXPORT_DIR`, затем конфиг, затем значения по умолчанию. `--config` / API `configFile` / `DORPIE_CONFIG` выбирает другой конфиг; отсутствие явно указанного файла — ошибка. Относительные пути в конфиге считаются от папки конфига. Явные относительные пути — от текущей папки CLI или папки проекта плагина. `~/` раскрывается в домашнюю папку пользователя.

Библиотека находится на машине, где работает Dorpie. Другая сессия на этой машине видит её автоматически. У разных серверов разные библиотеки. Для переноса копируйте согласованное состояние библиотеки и экспортов; одновременная запись с нескольких машин в сетевую файловую систему не поддерживается. Фоновая синхронизация не запускается.

Версии и экспорты публикуются целиком готовыми папками. Конкурирующие записи с одинаковым ожидаемым номером версии не перезаписывают друг друга. Прерванная операция может оставить скрытую папку `.pending-*`; чтение её игнорирует, а удалить её можно после остановки записывающего процесса. Автоматического срока хранения нет.

## Хранение и стоимость операций

Каждая версия исходника хранит полную JSON-спеку и метаданные. Каждый экспорт хранит запрошенные файлы, исходник, тему и описание экспорта; в библиотеке остаётся ещё одна маленькая запись, чтобы история переживала смену папки экспорта. Фонового индекса нет. `list` перебирает папки диаграмм и имена папок их ревизий, читает последние метаданные каждой диаграммы и сортирует совпадения. Страницы ограничивают ответ, а не этот проход. `history` перебирает имена ревизий и экспортов одной диаграммы и читает метаданные запрошенной страницы. Длинная история увеличивает работу с каталогами, большая библиотека — число чтений метаданных.

Включайте в резервную копию исходники и экспорты. На время снимка или восстановления остановите запись, сохраните также файлы своих тем, а после восстановления проверьте `settings`, `list`, `get` и `history`. Если перенести папки, абсолютные пути экспортов останутся привязаны к прежнему месту. Сбой между публикацией файлов экспорта и записью в каталог может оставить готовый экспорт вне истории; его `export.json` и файлы доступны в папке экспорта. Не удаляйте папку только потому, что её нет на странице истории.

## Node API

```js
import { createLibrary } from "dorpie/library";

const library = createLibrary(); // необязательные { libraryDir, exportDir, configFile }
const saved = await library.save(spec, { name: "Deploy flow", tags: ["deploy"] });
const opened = await library.get(saved.id);
await library.save(editedSpec, {
  id: opened.id,
  expectedRevision: opened.revision,
  change: "Add retry",
});
const exported = await library.export(saved.id, { formats: ["svg", "png"] });
await library.list({ query: "deploy", limit: 20 });
await library.history(saved.id);
```

`createLibrary(options?, directory?)` разрешает настройки один раз. Свойство `config` содержит пути. `get(id, revision?)`, `save(spec, metadata?)`, `list(filter?)`, `history(id, pagination?)` и `export(id, options?)` возвращают Promise. Параметры экспорта соответствуют `render`, с дополнительным `revision`; пути файлов тем считаются от `directory`. `LibraryError.code` принимает `INVALID_ARGUMENT`, `NOT_FOUND` или `CONFLICT`; ошибки проверки спеки и темы остаются прежними. Импорт библиотеки работ загружает рендер только при экспорте. Инструменты агента описаны в [plugin.ru.md](./plugin.ru.md).
