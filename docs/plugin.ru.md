# Плагин OpenCode / OpenCodez

[English](./plugin.md) · [Русский](./plugin.ru.md) · [Главная](../README.ru.md)

Dorpie — один пакет: CLI, Node-библиотека и плагин используют общий рендер и сохранённые диаграммы. Плагин работает внутри бэкенда OpenCode, не запускает сервер, браузер или фоновый индекс. PNG-рендер загружается только при экспорте.

## Установка

Для CLI нужен Node 20+. Установите релиз и подключите плагин:

```sh
npm install -g https://github.com/Krablante/dorpie/releases/download/v0.4.0/dorpie-0.4.0.tgz
dorpie plugin install --app opencodez
# Для upstream OpenCode:
# dorpie plugin install --app opencode
```

Перезапустите выбранное приложение/бэкенд. Команда добавляет небольшой загрузчик `plugins/dorpie.js` в глобальную папку конфигурации приложения. Существующий конфиг не переписывается. `--config-dir PATH` позволяет выбрать другой профиль. Повторная установка обновляет управляемый загрузчик; чужой файл по этому пути сохраняется и вызывает ошибку. Обновляйте глобальный пакет; если его папка установки изменилась, повторите команду подключения. Для отключения удалите этот загрузчик.

В новых загрузчиках с поддержкой входа пакета `./server` можно вместо этого добавить релиз прямо в `opencode.json` / `opencode.jsonc`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    "https://github.com/Krablante/dorpie/releases/download/v0.4.0/dorpie-0.4.0.tgz"
  ]
}
```

Выберите один способ установки, чтобы инструменты не регистрировались дважды. Архив релиза работает без публикации в npm. Для локальной разработки можно указать абсолютный путь к `src/opencode-plugin.js` в конфиге плагинов. Отдельный вход `./server` сохраняет обычный `import ... from "dorpie"` как API рендера.

## Инструменты агента

| Инструмент | Назначение |
| --- | --- |
| `dorpie_help` | `topic: "schema"`, `"themes"` или `"settings"`: схема спеки, список тем или действующие пути. |
| `dorpie_list` | Поиск `query`, необязательный фильтр `project`; страницы через `limit` и `offset`. |
| `dorpie_get` | Прочитать `id` и необязательный `revision`, включая редактируемый `spec`. |
| `dorpie_save` | Сохранить полный объект `spec`; необязательные name/description/tags/project/change. Для существующего `id` нужен `expectedRevision`. |
| `dorpie_history` | Версии исходников и сохранённые экспорты для `id`; необязательные `limit`/`offset`. |
| `dorpie_export` | Экспорт `id` и необязательного `revision`; formats/theme/scale/transparent/charset/systemFonts. По умолчанию все форматы. |

Рабочий цикл: **schema → save → export → просмотр PNG → get/редактирование/save/export**. Для возвращения к прошлой диаграмме начните с list/get. Источник — JSON; не редактируйте готовые SVG, PNG или ASCII. При неоднозначном поиске уточните выбор у пользователя. Save и export соблюдают разрешения `edit` хоста, включая ограничения Plan Mode. PNG-экспорт возвращает файловое вложение вместе с постоянными путями; для визуальной проверки нужна модель с vision или существующий инструмент просмотра изображений.

Инструменты не загружают весь каталог в системный промпт. Поиск и история возвращают ограниченные страницы метаданных. Исходники и экспорты переживают новые чаты, компакцию и перезапуск приложения. ID текущей сессии и сообщения записываются в версию исходника как информация о происхождении.

## Настройки и удалённые бэкенды

Плагин читает тот же [конфиг Dorpie](./library.ru.md#настройки), что и CLI. Большинству пользователей отдельные параметры плагина не нужны. Для переопределения в одном профиле OpenCode:

```json
{
  "plugin": [[
    "https://github.com/Krablante/dorpie/releases/download/v0.4.0/dorpie-0.4.0.tgz",
    { "libraryDir": "~/diagrams/library", "exportDir": "~/diagrams/exports" }
  ]]
}
```

Доступны `libraryDir`, `exportDir` и `configFile`. Относительные пути считаются от папки проекта бэкенда; для общей библиотеки разных проектов используйте абсолютные пути или `~/`. Настройки разрешаются при инициализации плагина; после изменения переподключитесь/перезапустите приложение.

Файлы принадлежат машине бэкенда. Браузер на другом компьютере видит PNG-вложения, но возвращённые файловые пути относятся к серверу. При доставке на серверы устанавливайте один пакет, сохраняя библиотеку каждого хоста. Плагин не требует изменений ядра OpenCode, учётных данных или сетевых запросов для рендера.
