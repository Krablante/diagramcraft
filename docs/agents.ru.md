# Использование Dorpie из агента

[English](./agents.md) · [Русский](./agents.ru.md) · [Главная](../README.ru.md)

Эта страница написана для ИИ-агентов и для людей, которые их настраивают. Всё описанное работает без GUI, браузера и сетевого доступа во время рендера.

## Подготовка

```sh
# глобальная установка из релизного tarball
npm install -g https://github.com/Krablante/dorpie/releases/download/v0.2.1/dorpie-0.2.1.tgz

# или запуск прямо из репозитория, без установки
node /path/to/dorpie/bin/dorpie.js <command>

dorpie schema             # полная JSON-схема спеки
dorpie themes             # id и описания тем
```

Примеры спек лежат в [`examples/`](../examples) в репозитории и в каталоге `examples/` установленного пакета.

## Рабочий цикл

1. **Написать или отредактировать одну JSON-спеку.** Она остаётся источником истины. Если пользователь просит изменение, правьте спеку — никогда не SVG, PNG или ASCII.
2. **Проверить до рендера.**
   ```sh
   dorpie validate spec.json          # для человека
   dorpie validate spec.json --json   # для машины
   ```
   Код возврата `2` означает, что спека некорректна; каждая проблема выводится с JSON-путём.
3. **Отрендерить.** SVG дешёвый, ASCII — самый дешёвый, PNG — для пользователя.
   ```sh
   dorpie render spec.json --format svg,ascii --out out/
   dorpie render spec.json --format png --scale 2 --out out/diagram.png
   ```
4. **Посмотреть на результат.** Для PNG откройте файл инструментом зрения и проверьте подписи, стрелки, пересечения и читаемость. Для быстрых итераций читайте ASCII — он показывает структуру, ветвления и подписи без растрирования.
5. **Поправить спеку и отрендерить снова.** Повторяйте, пока диаграмма не станет читаемой, затем отдайте запрошенные файлы.

## Фрагмент системного промпта

```
Ты умеешь создавать и редактировать диаграммы через CLI dorpie.
- Диаграмма — это одна JSON-спека; она редактируемый источник. Никогда не
  редактируй сгенерированные SVG/PNG/ASCII: правь спеку и рендери заново.
- Проверяй структуру по `dorpie schema` и валидируй через
  `dorpie validate <file>`. Исправляй все найденные проблемы до рендера.
- Рендери командой `dorpie render <file> --format svg,png,ascii`.
- Перед тем как сообщить об успехе, посмотри на PNG (vision) или ASCII сам.
- Выбирай тему по задаче: classic (нейтральная), paper (тёплая печать),
  glass (современная, полупрозрачная), midnight (тёмная), vivid (цветная),
  blueprint (техническая), mono (чёрно-белая печать). Список — `dorpie themes`.
- Подписи держи короткими; детали — в `note`; на развилках подписывай связи
  yes/no; группы — для фаз, а не для украшения.
```

## Выбор темы

| Задача | Тема |
| --- | --- |
| документация, отчёты, спокойная печатная подача | `paper` |
| обычные блок-схемы, которые будут править и другие | `classic` |
| продуктовые визуалы, лендинги, современные презентации | `glass` |
| тёмные слайды или терминалы | `midnight` |
| объяснения с цветовым кодированием этапов | `vivid` |
| инженерия, инфраструктура, техническая документация | `blueprint` |
| печать, фотокопии, строгий монохром | `mono` |

## Как писать спеки, которые хорошо рендерятся

- Держите подписи узлов короче ~24 символов; остальное — в `note`.
- 8–20 узлов на диаграмму. Всё большее разбивайте на две диаграммы или группируйте.
- Id — это стабильные ручки: сохраняйте их при правках, чтобы связи не рвались.
- Осознанно выбирайте `kind`: `terminal` для начала/конца, `decision` для настоящих развилок, `data` для входов/выходов, `note` для оговорок, `junction` для тихих слияний.
- Для пайплайнов и таймлайнов используйте `direction: "LR"`, для процедур — `TB`.
- Группы — для фаз (`Prepare`, `Publish`, `Roll out`) и повторяющихся блоков (`× N`). Группы не двигают узлы; это визуальные зоны.
- Для правки цветов предпочитайте `style` в спеке, а файл темы — только когда нужна переиспользуемая визуальная система.
- Неизвестные поля отклоняются, а валидация называет их с путём: опечатка падает сразу, а не молча игнорируется.

## Типичные ошибки

| Ошибка | Что получится |
| --- | --- |
| редактирование SVG/PNG вместо спеки | следующий рендер перезапишет правку |
| дублирующиеся id узлов | `nodes[2].id: duplicate node id "build" (first used by nodes[1])` |
| связь в несуществующий узел | `edges[1].to: unknown node "shiping"` |
| петля на себя | `edges[0]: self-loops are not supported; add a junction node instead` |
| подпись у junction | `nodes[3].label: junction nodes do not render a label` |
| опечатка в имени поля | `nodes[0].lable: unknown field "lable"` |
| длинные подписи | узлы становятся широкими, раскладка — высокой; переносите через `\n` или сокращайте |
| группы как контейнеры раскладки | узлы могут оказаться вне зоны, если поток разъехался; управляйте потоком через `direction` и порядок узлов |

## Программное использование

```js
import { render, parseSpec, listThemes } from "dorpie";

const spec = parseSpec(JSON.parse(specText));   // бросает SpecError с .issues
const { svg, png, ascii } = await render(spec, {
  formats: ["svg", "png", "ascii"],
  theme: "paper",          // id встроенной темы или путь к JSON-файлу темы
  scale: 2,
});
```

`render` никогда не пишет файлы. CLI лишь добавляет вокруг него ввод-вывод. Полное описание — опции, поля результата, ошибки и экспорты нижнего уровня — в [api.ru.md](./api.ru.md).
