# Справочник CLI

[English](./cli.md) · [Русский](./cli.ru.md) · [Главная](../README.ru.md)

`dorpie` — один исполняемый файл для рендера, сохранённых диаграмм и подключения плагина. Обычный рендер читает JSON из файла или стандартного ввода и использует только аргументы и спеку. Команды библиотеки также читают необязательный конфиг Dorpie. Нужен Node 20 или новее.

| Команда | Назначение |
| --- | --- |
| `dorpie render <spec.json\|->` | Отрендерить спеку в один или несколько форматов. |
| `dorpie validate <spec.json\|->` | Разобрать и проверить спеку без рендера. |
| `dorpie themes [id]` | Показать список встроенных тем или напечатать одну раскрытую тему в JSON. |
| `dorpie schema` | Напечатать JSON-схему спеки. |
| `dorpie init [file.json]` | Создать стартовую спеку. |
| `dorpie save <spec.json\|->` | Создать сохранённую диаграмму; обновить через `--id` и `--expected-revision`. |
| `dorpie list [query]` | Найти диаграммы; фильтр `--project`, страницы `--limit`/`--offset`. |
| `dorpie get <id>` | Прочитать метаданные и JSON; `--spec` выводит исходник, `--revision N` выбирает версию. |
| `dorpie history <id>` | История исходников и экспортов с `--limit`/`--offset`. |
| `dorpie export <id>` | Сохранить экспорт; можно выбрать `--revision N` и параметры рендера. |
| `dorpie settings` | Показать разрешённые настройки библиотеки. |
| `dorpie plugin install` | Подключить пакет к `--app opencodez` (по умолчанию) или `--app opencode`. |
| `dorpie --help`, `dorpie --version` | Справка и версия. |

## render

```
dorpie render <spec.json|-> [options]
```

| Флаг | Смысл | По умолчанию |
| --- | --- | --- |
| `-t, --theme <id\|file.json>` | Перекрыть тему из спеки: id встроенной темы или путь к JSON-файлу темы. | `theme` из спеки, затем `classic` |
| `-f, --format <list>` | Список форматов через запятую: `svg,png,ascii`. | `output.formats` из спеки, затем `svg` |
| `-o, --out <path\|->` | Файл, каталог или `-` для stdout. | рядом со спекой |
| `--scale <n>` | Множитель масштаба PNG. | `output.scale` из спеки, затем `2` |
| `--transparent` | Убрать фон холста в SVG и PNG. | `false` |
| `--system-fonts` | Разрешить системные шрифты при рендере PNG. | `false` |
| `--charset <unicode\|ascii>` | Набор символов для ASCII-вывода. | `output.charset` из спеки, затем `unicode` |
| `-q, --quiet` | Не печатать пути записанных файлов. | выключен |

Пути вывода работают так:

- Без `--out` файлы пишутся рядом со спекой и называются по ней: `spec.svg`, `spec.png`, `spec.txt`. Для ASCII используется расширение `.txt`.
- `--out dir/` или путь к существующему каталогу кладёт файлы в этот каталог под именем исходной спеки.
- `--out file` принимает ровно один формат; с несколькими форматами команда завершается кодом `2`.
- `--out -` пишет ровно один формат в stdout и не добавляет ничего лишнего. Несколько форматов в stdout отклоняются.
- Вход `-` читает спеку из stdin. Без `--out` файлы появятся в текущем каталоге с базовым именем `diagram`, например `diagram.svg`.
- Существующие файлы вывода перезаписываются при каждом рендере. Сгенерированные SVG, PNG и ASCII — это вывод, а не редактируемый источник.

```sh
# все форматы, которые запрошены в спеке, рядом со спекой
dorpie render spec.json

# переопределить форматы и каталог вывода
dorpie render spec.json --format svg,png --out out/

# один формат в один файл, с другой темой и масштабом
dorpie render spec.json --format png --theme glass --scale 3 --out out/diagram.png

# спека из stdin, ASCII в stdout
cat spec.json | dorpie render - --format ascii --out - > diagram.txt
```

## validate

`validate` разбирает спеку и показывает все проблемы с JSON-путями; файлы не пишутся. Корректная спека печатает короткую сводку:

```sh
$ dorpie validate examples/quickstart.json
ok: 6 nodes, 6 edges, 0 groups, theme "classic"

$ dorpie validate examples/quickstart.json --json
{"ok":true,"theme":"classic","nodes":6,"edges":6,"groups":0}
```

Некорректная спека завершается кодом `2`:

```sh
$ dorpie validate broken.json
spec error: 2 problems
  nodes[1].id: duplicate node id "build" (first used by nodes[0])
  edges[0].to: unknown node "ships"
```

Справочник полей и JSON-схема — в [spec.ru.md](./spec.ru.md) и `dorpie schema`.

## themes

Без аргумента `themes` печатает список id и описаний встроенных тем. С id — печатает полностью раскрытую тему (слитую с базовыми значениями) в JSON; удобная заготовка для своей темы:

```sh
dorpie themes                             # id, заголовок и описание построчно
dorpie themes --json                      # те же метаданные в JSON
dorpie themes paper > my-theme.json       # записать полный файл темы
dorpie render spec.json --theme my-theme.json
```

Неизвестный id завершается кодом `2` и списком доступных тем.

## schema

`schema` печатает JSON-схему спеки в stdout — для валидации в редакторе или для агентов, которым нужна точная структура:

```sh
dorpie schema > diagram.schema.json
```

## init

`init` создаёт небольшую стартовую спеку, которая запрашивает SVG, PNG и ASCII, и печатает путь к записанному файлу:

```sh
dorpie init                # создаст ./diagram.json
dorpie init hello.json
dorpie init hello.json --force   # перезаписать существующий файл
```

Без `--force` команда отказывается перезаписывать существующий файл и завершается кодом `2`.

## Коды возврата

Команды библиотеки выводят JSON. Они принимают `--config`, `--library-dir` и `--export-dir`. `save` принимает `--name`, `--description`, `--tags` (через запятую), `--project` и `--change`. `export` принимает параметры рендера выше, кроме `--out`/`--quiet`; папку задаёт `--export-dir`. По умолчанию экспортируются SVG, PNG и ASCII. Хранение, конфликты и настройки описаны в [library.ru.md](./library.ru.md); установка и `--config-dir` — в [plugin.ru.md](./plugin.ru.md).

| Код | Смысл |
| --- | --- |
| `0` | Успех. |
| `2` | Некорректная спека, неизвестная тема или неверные аргументы CLI; в сообщении сказано, что исправить. |
| `1` | Ошибка времени выполнения: например, нечитаемый входной файл или ошибка ввода-вывода. |

Ошибки спеки и тем уходят в stderr с понятными путями, поэтому скрипт может опираться на код возврата и при этом сохранить сообщение в лог.

Ошибки библиотеки `INVALID_ARGUMENT`, `NOT_FOUND` и `CONFLICT` также возвращают `2`. При конфликте прочитайте текущую версию и согласуйте изменения перед сохранением.

## Типичные проблемы

| Симптом | Что проверить |
| --- | --- |
| `dorpie: command not found` | Глобальный каталог bin из npm не в `PATH`. Найдите его через `npm prefix -g` или запустите из репозитория: `node /path/to/dorpie/bin/dorpie.js`. |
| `unknown theme "..."` | Выполните `dorpie themes`. Своя тема считается путём только если заканчивается на `.json` или содержит `/`; иначе это должен быть id встроенной темы. |
| `theme file not found` | Относительные пути тем разрешаются от текущего рабочего каталога, а не от файла спеки. Укажите абсолютный путь или сначала перейдите в нужный каталог. |
| `cannot write ... to a single file` / `stdout can only carry one format` | `--out file` и `--out -` принимают один формат. Передайте каталог или разделите команду по форматам. |
| PNG выглядит иначе, чем SVG | SVG ссылается на имена семейств, и зритель подставляет отсутствующие системные шрифты; PNG использует встроенные OFL-шрифты. Для одинакового результата держитесь встроенных семейств или передайте `--system-fonts`, приняв зависимость от машины. |
| Текст вне латиницы, греческого и кириллицы рендерится квадратами | Встроенные шрифты покрывают не все письменности. Используйте `--system-fonts` с подходящим установленным шрифтом или добавьте шрифт в форк (см. [themes.ru.md](./themes.ru.md)). |
| `unknown field "..."` при проверке | Опечатка или неподдерживаемое поле; точную структуру показывает `dorpie schema`. |
| `junction nodes do not render a label` | Junction-узлы — это тихие точки слияния. Уберите подпись или выберите другой вид узла. |
| `self-loops are not supported` | Связь ведёт из узла в него же. Добавьте junction или проведите повторную попытку через другой узел. |
| Диаграмма «не изменилась» | Файлы вывода перезаписываются при каждом рендере, но только из спеки. Правьте JSON, а не SVG/PNG, и рендерите снова. |

Поля спеки описаны в [spec.ru.md](./spec.ru.md), рабочий процесс для агентов — в [agents.ru.md](./agents.ru.md).
